# Architecture

## 1. 目的

認証サーバーと参加アプリの論理構成、通信経路、責任分界を説明する。

## 2. 論理構成

```text
                 +----------------------+
                 |      auth-server     |
                 | 認証・ユーザー管理   |
                 | 共通ロール・アプリ管理|
                 +----------+-----------+
                            |
                   認証・連携インターフェース
                            |
              +-------------+-------------+
              |                           |
    +---------v----------+      +---------v----------+
    | participant-app    |      | participant-app    |
    | (sample-app)       |      | (future app)       |
    | 業務機能・固有権限  |      | 業務機能・固有権限  |
    +--------------------+      +--------------------+
```

## 3. 責任分界

### auth-server
- 共通ユーザーの認証と管理
- 共通ロールの管理
- 参加アプリの登録・利用許可
- 参加アプリとの認証連携

### participant-app-base
- 認証サーバーとの連携処理
- 参加アプリ側の認証状態・アクセス制御を支援
- 参加アプリで共通利用する処理を提供

### 各参加アプリ
- アプリ固有の業務データ・機能
- アプリ固有ロールと権限
- アプリ固有の画面・API

## 4. 通信・データフロー

具体的なエンドポイント、HTTPメソッド、署名・暗号化方式、データ形式は、実装と既存仕様を確認して記載する。未確認の内容を推測で確定仕様として扱わない。

## 5. 配置・インフラ構成

本番・検証環境ごとに、ホスト、コンテナ、ネットワーク、DB、キャッシュ、TLS終端、バックアップを記録する。
