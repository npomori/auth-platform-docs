# Roles and Permissions

## 1. 目的

共通ロール、参加アプリの利用許可、参加アプリ固有ロールの関係と権限変更ルールを定義する。

## 2. 権限の階層

| 管理対象 | 管理主体 | 説明 |
|---|---|---|
| 共通ロール | auth-server | システム共通のユーザー権限 |
| 参加アプリの利用許可 | auth-server | ユーザーが対象アプリを利用できるか |
| アプリ固有ロール | 各参加アプリ | 対象アプリ内の業務権限 |

## 3. ロールの考え方

- `admin`、`app_admin` は基本的なサーバー設定・管理に関わるロールとして扱う。
- 日常的な運用は、用途に応じた他のロールに分担する。
- `manager` は参加アプリ内のロールを管理できる。
- `manager` は必要に応じて `modifier` 等のアプリ固有ロールを併せ持てる。
- 共通ロールと参加アプリの組み合わせにより、参加アプリ内で有効な権限範囲を決める。

## 4. 権限変更ルール

- `user` から `manager` への昇格は `admin` のみが実行できる。
- `manager` から `admin` への昇格は認めない。
- 他の `manager` の権限変更は `admin` のみが実行できる。
- 最後の `admin` は降格・削除できない。
- `manager` が管理できる対象・操作範囲は、割り当てられた参加アプリの範囲に限定する。

## 5. 実装時の確認事項

- `admin` と `app_admin` の包含関係
- 共通ロールからアプリ固有ロールへの権限マッピング
- 複数ロールを持つ場合の評価規則
- ロール変更の監査ログ
- 権限変更が既存セッションへ反映されるタイミング

## 6. 原則

認可判定はサーバー側で行う。画面上の表示制御だけをアクセス制御の根拠にしない。
