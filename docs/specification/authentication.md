# Authentication Specification

## 1. 目的・範囲

認証サーバーがユーザーを認証し、参加アプリが認証結果を安全に利用するための共通仕様を定義する。

## 2. 認証方式

現行実装で採用している方式（例: WebAuthn／パスキー）を、auth-server の実装と照合して記載する。

## 3. 認証連携フロー

以下の各段階について、実際のエンドポイント・パラメーター・検証条件を明記する。

1. 参加アプリから認証開始
2. 認証サーバーへの遷移
3. ユーザー認証
4. 認証結果の参加アプリへの返却
5. 参加アプリ側での結果検証
6. 参加アプリ側のログイン状態確立

## 4. セキュリティ要件

- state等のリクエストと応答の紐付け
- リダイレクト先の許可リスト検証
- リプレイ攻撃への対策
- 認証結果の完全性・真正性の検証
- 秘密情報の保護とログへの非出力

## 5. エラー処理

認証失敗、キャンセル、期限切れ、不正な応答、通信障害の扱いを定義する。

## 6. 未確定事項

実装確認後、プロトコル、API、データ形式、タイムアウト、再試行条件を追記する。
